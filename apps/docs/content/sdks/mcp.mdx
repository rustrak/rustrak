# MCP server

Rustrak has a built-in [Model Context Protocol](https://modelcontextprotocol.io) server. Turn it on and Claude, Cursor, VS Code or any other MCP client can read and triage your errors with 79 tools. There is nothing to install: the client connects to your Rustrak instance at `/mcp`.

```
┌─────────────────────┐   Streamable HTTP    ┌─────────────────────┐
│  AI client          │ ───────────────────▶ │  Rustrak server     │
│  (Claude, Cursor…)  │   POST /mcp          │  /mcp  →  same      │
└─────────────────────┘   Bearer <token>     │  handlers as /api   │
                                             └─────────────────────┘
```

Every tool runs the same handler as the matching REST endpoint, so it has the same permission checks, the same validation and the same response shape as the [API](/api-reference).

> Replacing `@rustrak/mcp`: the npm package is deprecated. The tools keep their names, so swapping the client configuration below for your old `npx @rustrak/mcp` entry is the whole migration.

## Setup

### 1. Turn it on

In the dashboard, open **Settings → AI assistants (MCP)** and switch the MCP server on. Only an instance admin can do this, and it is off by default: until someone turns it on, `/mcp` answers 404.

The same page shows your endpoint URL and the configuration snippets below, already filled in.

### 2. Connect your assistant

There are two ways in, and both act as one user: the assistant can do what that user can, and nothing more. A member only sees the projects they belong to; an admin can do anything an admin can, including the destructive tools.

#### Web assistants: sign in and approve (claude.ai, ChatGPT)

Add a custom connector with your endpoint URL, `https://your-rustrak.example.com/mcp`, and nothing else. The assistant opens Rustrak, you sign in (SSO included) and approve it, and it is connected. No token to copy.

Under the hood this is the OAuth 2.1 flow the MCP specification asks for, with Rustrak as its own authorization server: the assistant identifies itself with a [Client ID Metadata Document](https://modelcontextprotocol.io/specification/2026-07-28/basic/authorization/client-registration), proves its request with PKCE, and gets an access token that lasts an hour and works only at `/mcp`. Its refresh token works once: every refresh replaces both.

Every connection is listed under **Settings → AI assistants (MCP) → Connected assistants**, where disconnecting one cuts it off at once. A refresh token presented twice means it was stolen, and ends the connection for whoever holds it.

> **Signing in needs `PUBLIC_URL`**, set to the address assistants reach Rustrak on (for example `https://rustrak.example.com`). The authorization server and the resource the tokens are bound to are both named after it, never after the request or the bind address. Without it there is no sign-in to discover, and the settings page says so; API tokens still work. The consent screen is a dashboard page, served at `DASHBOARD_URL` when the dashboard runs on its own host, so an API-only deployment connects with tokens.

#### Desktop and CLI clients: an API token (Claude Code, Cursor, VS Code)

Create a token in **Settings → API Tokens** (see [API Tokens](/usage/tokens)) and pass it as a header.

**Claude Code**

```bash
claude mcp add --transport http rustrak https://your-rustrak.example.com/mcp \
  --header "Authorization: Bearer your-40-char-token"
```

**Cursor** (`~/.cursor/mcp.json`) and other clients that read `mcpServers`:

```json
{
  "mcpServers": {
    "rustrak": {
      "type": "http",
      "url": "https://your-rustrak.example.com/mcp",
      "headers": {
        "Authorization": "Bearer your-40-char-token"
      }
    }
  }
}
```

**VS Code** (`.vscode/mcp.json`, or **MCP: Open User Configuration**). VS Code asks for the token the first time and keeps it encrypted, so the file holds no secret and can be committed:

```json
{
  "inputs": [
    {
      "type": "promptString",
      "id": "rustrak-token",
      "description": "Rustrak API token",
      "password": true
    }
  ],
  "servers": {
    "rustrak": {
      "type": "http",
      "url": "https://your-rustrak.example.com/mcp",
      "headers": {
        "Authorization": "Bearer ${input:rustrak-token}"
      }
    }
  }
}
```

`"type": "http"` matters: a client that reads a URL without it, such as Claude Code's `.mcp.json`, takes the entry for a local stdio server. The settings page shows these snippets with your own URL filled in.


## How it works

- **Stateless.** `/mcp` speaks protocol version `2026-07-28` over Streamable HTTP. Every call is one `POST` that carries its own token, and the server keeps nothing between calls, so the endpoint costs nothing while idle.
- **Bearer only.** `/mcp` takes an OAuth access token or an API token. The dashboard's session cookie is not accepted, so a browser tab cannot call tools for its user, and an OAuth token is not accepted anywhere but `/mcp`.
- **Errors are results.** A failed call comes back as tool output with `isError: true`, so the assistant reads what went wrong instead of losing the call.
- **Destructive tools are marked** with `destructiveHint`, and clients that support it ask before running them. The storage cleanup tools also require an explicit `confirm=true`.

| Tool | Description |
|---|---|

| `update_issue_status` | Set status (unresolved, resolved, ignored, resolvedInNextRelease) and priority |
| `assign_issue` | Assign an issue, or clear the assignment |
| `bulk_update_issues` | Set status or priority on many issues |
| `delete_issue` | ⚠️ Delete an issue and its events |
| `bulk_delete_issues` | ⚠️ Delete issues by id or by state |
| `get_issue_hashes` | Grouping hashes that map to an issue |
| `get_issue_tag_values` | Values of one tag across an issue |
| `get_issue_aggregates` | Affected users and top tags |

| `get_issue_activity` | Status changes and comments |
| `comment_on_issue` | Add a comment |
| `bookmark_issue` / `subscribe_issue` / `mark_issue_seen` | Your bookmark, subscription and seen state |
| `list_user_reports` / `submit_user_report` | User feedback attached to an issue |

### Team, tokens and storage

Team, invitation and storage tools need an admin. Token tools work on the caller's own tokens; an admin can also manage everyone else's. Project-member tools need a global admin or an admin of that project. See [Team & Access](/usage/team).

| Tool | Description |
|---|---|
| `list_team_members` / `update_member_role` | Users and their global role |
| `remove_team_member` | ⚠️ Remove a user from the instance |
| `create_invitation` / `list_invitations` | Invite by email |
| `revoke_invitation` | ⚠️ Revoke a pending invitation |
| `list_project_members` / `set_project_member` | A project's members and their roles |
| `remove_project_member` | ⚠️ Remove a user from a project |
| `list_tokens` / `get_token` / `create_token` | API tokens |
| `revoke_token` | ⚠️ Revoke a token |
| `get_storage_summary` / `get_storage_by_project` | What is using storage |
| `preview_storage_cleanup` / `execute_storage_cleanup` | ⚠️ Delete data older than N days, with `confirm=true` |
| `get_storage_cleanup_status` | Progress of the running cleanup |
| `preview_storage_source_maps_gc` / `gc_storage_source_maps` | ⚠️ Remove orphaned source maps, with `confirm=true` |
| `get_retention` / `preview_retention` | Retention settings and what they would delete |
| `update_retention` / `run_retention` | ⚠️ Save or enforce retention, with `confirm=true` |

> Tools marked ⚠️ are annotated with `destructiveHint`.

- *"List the unresolved issues in project 1"*
- *"Show me the stack trace of the latest event of issue abc-123"*
- *"Which transactions got slower this week?"*

- *"Invite alice@example.com as a member and give me the invite link"*

## Security notes

- Error events are written by the applications you monitor, so their text can be anything, including instructions aimed at an assistant. The server tells clients to treat event content as data, but review what an assistant proposes before letting it run destructive tools.
- Give an assistant the least privileged token that does the job: a member's token cannot touch projects that member does not belong to.
- Disconnecting the assistant, revoking its token, disabling its user or turning the switch off cuts it off at once.
- The consent screen cannot be framed by another site, and an authorization request whose client or redirect Rustrak cannot verify is refused without sending the browser anywhere.

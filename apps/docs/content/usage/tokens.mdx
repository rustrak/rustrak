# API Tokens

An API token lets a script, a CI job or another tool use Rustrak's API: `sentry-cli` uploading [source maps](/usage/source-maps), a deploy creating a [release](/usage/releases), an AI assistant through the [MCP server](/sdks/mcp).

It is not the DSN. The DSN only sends events; a token reads data and changes things.

## Create a token

<InteractiveDemo src="/demos/tokens.openshowcase" />

Go to **Settings → API Tokens**, click **New Token**, give it a description that says where it is used ("CI deploy") and click **Create Token**. Copy it from the dialog. You can copy it again later from the token list.

A token acts as the user who created it: it sees the same projects and can do the same things. Removing that user deletes their tokens.

## Use it

Send it in the `Authorization` header:

```bash
curl -H "Authorization: Bearer $RUSTRAK_TOKEN" "$RUSTRAK_URL/api/projects"
```

Tools that speak Sentry's API, like `sentry-cli` and the bundler plugins, take it as `SENTRY_AUTH_TOKEN`. The [API reference](/api-reference) lists every endpoint.

## Manage tokens

**Settings → API Tokens** lists your tokens with when each was created and last used. Delete one to revoke it at once. To rotate a token, create the new one, update whatever uses it, then delete the old one.

A `401` means the header is missing or malformed, or the token was deleted. A token is 40 hexadecimal characters.

# Team & Access

One Rustrak serves a whole team. Each person has their own login, and roles decide which projects they see and what they can do there.

## Roles

There are two layers.

**Instance role.** Every user is an **Admin** or a **Member**. Admins see every project and manage the team. Members see only the projects they were added to.

The first account, created by `CREATE_SUPERUSER`, is the primary user: it cannot be demoted or removed, so the instance can never be locked out.

**Project role.** Members get a role on each project they join:

| Role | Can |
|---|---|
| **Viewer** | Read issues, events and the project |
| **Editor** | Also resolve, archive and delete issues, and change the project |
| **Admin** | Also delete the project and manage its members |

Instance admins have full access to every project without being added.

## Invite someone

There is no open sign-up; only admins invite.

1. Go to **Settings → Members**.
2. Under **Invite a member**, enter the email, pick **Member** or **Admin** and, if you want, turn on **Send the invite by email**.
3. Click **Invite**. Without the email, the invitation link is copied to your clipboard: share it yourself.

**Pending invitations** lets you copy the link again, resend the email or revoke the invitation. A link works once and expires after 48 hours.

The invitee opens the link, sets a password and is signed in, with the email and role from the invitation.

With [single sign-on](/configuration/sso), people can also sign in through your identity provider.

### Invitation emails

They go out through the same SMTP as alert emails: the first enabled email integration in **Settings → Integrations**, with the `SMTP_*` [environment variables](/configuration/environment) filling in whatever it leaves empty. Either one alone is enough. The link uses `DASHBOARD_URL`, else `PUBLIC_URL`; without an SMTP host and one of those, the switch stays off.

If the email fails, the invitation is still created and its link copied, so you can share it yourself or resend it later.

## Manage the team

In **Settings → Members**, the **Actions** menu next to each person changes their instance role or removes them. Removing a user revokes their access and their API tokens. You cannot remove yourself, the primary user or the last admin.

## Project members

Open a project's **Settings → Members** to add someone with a project role, change their role or remove them. A project always keeps at least one admin. Whoever creates a project becomes its admin.

## API

[API tokens](/usage/tokens) act as the user who made them, with that user's projects and permissions. Admins can manage the team over the API:

```bash
# The team
curl -H "Authorization: Bearer $RUSTRAK_TOKEN" "$RUSTRAK_URL/api/team"

# Invite someone; the response holds the invitation token
curl -X POST -H "Authorization: Bearer $RUSTRAK_TOKEN" -H "Content-Type: application/json" \
  -d '{"email": "lena@example.com", "role": "member"}' "$RUSTRAK_URL/api/invitations"

# Same, and email the invite
curl -X POST -H "Authorization: Bearer $RUSTRAK_TOKEN" -H "Content-Type: application/json" \
  -d '{"email": "lena@example.com", "role": "member", "send_email": true}' "$RUSTRAK_URL/api/invitations"

# Email the invite link again
curl -X POST -H "Authorization: Bearer $RUSTRAK_TOKEN" "$RUSTRAK_URL/api/invitations/TOKEN/resend"

# Add user 2 to project 1 as an editor
curl -X PUT -H "Authorization: Bearer $RUSTRAK_TOKEN" -H "Content-Type: application/json" \
  -d '{"user_id": 2, "role": "editor"}' "$RUSTRAK_URL/api/projects/1/members"
```

| Situation | Answer |
|---|---|
| A member opens a project they are not in | `404`, so the project's existence does not leak |
| A viewer resolves or deletes an issue | `403` |
| A non-admin calls a team or invitation endpoint | `403` |
| `POST /auth/register` | `403`: sign-up is by invitation only |
| `send_email: true` with no SMTP host, or no `DASHBOARD_URL` or `PUBLIC_URL` | `400`, naming `send_email` |
| Resending an expired or accepted invitation | `400` |
| Removing the last admin of the instance or a project | `409` |

# Logs

Logs are the structured lines your app writes as it runs: "order created", "carrier quote took 900 ms". Rustrak keeps them per project under **Logs**, apart from issues, so you can see what the app was doing before something broke. They are not grouped: every line is stored and shown as it came.

## Send logs

Logs are off by default in Sentry SDKs. Turn them on in `Sentry.init` and use the SDK's logger:

```javascript
import * as Sentry from '@sentry/node';

Sentry.init({
  dsn: 'YOUR_DSN',
  enableLogs: true,
});

Sentry.logger.info('Order created', { orderId: 9182, total: 54.9 });
Sentry.logger.warn('Carrier quote slow', { carrier: 'dhl', ms: 1830 });
Sentry.logger.error('Payment webhook signature mismatch');
```

Rustrak takes Sentry's `log` envelope item, so any SDK version that sends logs works. Older JavaScript SDKs put the switch under `_experiments: { enableLogs: true }`. The SDK sends logs in batches, so they show up a few seconds later; call `Sentry.flush()` before a script exits.

Each line keeps its level, message, timestamp and attributes, each attribute with its type. A line written inside an active span also carries the span's trace and span IDs.

## Levels

| Level | Severity number |
|---|---|
| `trace` | 1 |
| `debug` | 5 |
| `info` | 9 |
| `warn` | 13 |
| `error` | 17 |
| `fatal` | 21 |

A line sent without a level is stored as `info`. An unknown level is kept as sent, with no severity number.

## Find a line

**Logs** shows the newest lines first, with a chart of the volume by level above them.

- Type in the search bar to find lines whose message contains the text, ignoring case.
- `level:error` keeps one level; `trace:<trace id>` keeps one trace.
- The window button (`14d` by default) sets how far back to look.

Click a line to open it: the full time, severity, trace ID and every attribute. **Logs in this trace** lists the other lines from the same request.

## API

Read logs with an [API token](/usage/tokens):

```bash
curl -H "Authorization: Bearer $RUSTRAK_TOKEN" \
  "$RUSTRAK_URL/api/projects/3/logs?level=error&query=renewal&period=7d&per_page=50"
```

| Parameter | What it does |
|---|---|
| `level` | One level |
| `trace_id` | One trace |
| `query` | Message contains this text, ignoring case |
| `period` | Window such as `24h`, `7d`, `14d`. All time when absent |
| `page`, `per_page` | Pagination. `per_page` is 20 by default, at most 100 |

`GET /api/projects/{id}/logs/{log_id}` returns one line and `GET /api/projects/{id}/logs/volume` the counts behind the chart. The [MCP server](/sdks/mcp) reads logs too.

Logs count toward storage and are removed by retention like the rest of the data. See [Storage](/usage/storage).

# Overview

Rustrak is a self-hosted error tracker that speaks the Sentry protocol. Any Sentry SDK you already use can send to it: change the DSN and nothing else.

## How it works

```text
Your app → Sentry SDK → Rustrak server → SQLite or PostgreSQL
                         (API + dashboard on :8080)
```

The SDK sends events to the server. The server groups them into issues and stores them in the database. The dashboard is compiled into the same server, so one process on one port answers both the API and the UI.

It is one container of about 20 MB that idles under 100 MB of memory, with ingestion under 50 ms. A VPS with 512 MB to 1 GB runs it comfortably. There is no per-event pricing and no event limit.

## Database backends

Each Docker image is compiled for one database. Both include the dashboard.

| Image tag | Backend | Use it for |
|-----------|---------|------------|
| `latest`, `vX.Y.Z` | SQLite | Personal projects and low traffic. Nothing else to run |
| `postgres`, `vX.Y.Z-postgres` | PostgreSQL | Teams, high volume, concurrent writes |

SQLite is the default. [Database backends](/configuration/database) compares the two.

## What it tracks

- Errors and exceptions, with stack traces and source context, grouped into [issues](/usage/issues) that you resolve, mute or reopen
- [Source maps](/usage/source-maps) for JavaScript, including Hermes and React Native, and [debug files](/usage/debug-files) for Android, JVM and iOS
- Transactions and spans
- Release health and sessions
- [Logs](/usage/logs)
- [Crons](/usage/crons): missed, failed and overrunning scheduled jobs
- [AI agent](/usage/agents) traces
- User feedback, with its screenshots

Around it: [alerts](/usage/alerts) to Slack, email and webhooks, [teams and roles](/usage/team), [API tokens](/usage/tokens), [GitHub](/configuration/github) and [GitLab](/configuration/gitlab) integration, [single sign-on](/configuration/sso), [storage and retention](/usage/storage) and an [MCP server](/sdks/mcp) for AI assistants.

## What it does not track

The server accepts these from an SDK and drops them:

- Attachments on error events
- Session replays
- Profiling
